# A4 사전 등록 예측 — `content-visibility: auto`

> **측정 전에 작성.** 2026-09-17, 하네스 완성 직후 / 측정 실행 전.

## 검증할 것

`content-visibility: auto` 는 화면 밖 요소의 **렌더링 작업을 건너뛴다**고 알려져 있다.
[조사 문서](../../../docs/01-landscape-2026.md#4-웹-플랫폼-레이어--interop-2026)에 적어둔 통용 수치는 *"layout+paint 단계 30~60% 절감"* 인데, 이건 **페이지에 따라 달라지는 상대값**이라 검증 기준으로 쓸 수 없다.

대신 **비용의 증가 양상**을 본다. 이게 훨씬 날카롭게 갈린다.

| | 예측 |
|---|---|
| `plain` | 레이아웃·페인트 비용이 **항목 수 N에 비례** — 화면 밖 8000개도 전부 계산 |
| `cv-auto` | **N과 거의 무관하게 평탄** — 화면에 보이는 ~10개만 계산 |

## 측정 방법

DOM 생성 비용을 제거하기 위해 **리스트를 먼저 만들어 놓고**(트레이스 밖), 그 다음 **강제 리레이아웃 8회**를 트레이스한다.
매 회차 컨테이너 폭(`--itemW`)을 760↔720px 로 바꿔 자식 전체의 레이아웃을 무효화한다.

| 항목 | 값 |
|---|---|
| N | 100 / 500 / 2000 / 8000 |
| 모드 | `plain` · `cv-auto` · `cv-nosize` |
| 리레이아웃 | 8회 (각 회차 rAF 2번 대기) |
| 지표 | 트레이스의 `Layout` · `Paint` · `UpdateLayoutTree` · `PrePaint` 횟수와 총 시간 |
| 격리 | 설정마다 Chrome 새로 기동 (A2 교훈) |
| 반복 | 3회 |

## 예측

### 수치

`Layout` 총 시간이 N에 대해:

| 모드 | N=100 → N=8000 (80배) | 예상 증가 |
|---|---|---|
| `plain` | 선형 | **40배 이상** |
| `cv-auto` | 평탄 | **5배 미만** |

`Paint` 이벤트 **횟수**:

| 모드 | N=8000 |
|---|---|
| `plain` | N에 비례해 수천~수만 회 |
| `cv-auto` | 화면에 보이는 항목 수준 (수십 회) |

### 핵심 주장

| # | 주장 | 뜻 |
|---|---|---|
| **C1** | `cv-auto` 의 `Layout` 시간이 N=8000에서 N=100 대비 **5배 미만** 증가 | 화면 밖은 정말 건너뛴다 |
| **C2** | `plain` 의 `Layout` 시간은 N에 대해 **선형**(8000/100 ≥ 40배) | 대조군이 제대로 비싼지 확인 |
| **C3** | N=8000에서 `cv-auto` 의 `Paint` 횟수가 `plain` 대비 **90% 이상 감소** | 페인트도 건너뛴다 |
| **C4** | `cv-nosize` 의 `scrollHeight` 가 `cv-auto` 보다 **작다** | `contain-intrinsic-size` 없으면 크기를 0으로 잡아 스크롤 길이가 틀어진다 |

**C1이 이 실험의 전부다.** "30~60% 빨라진다"가 아니라 **"비용이 콘텐츠 양과 무관해진다"** 가 이 기능의 진짜 성질이라는 주장이다.

## 판정

- C1·C2 성립 → **통과**
- C1 실패 (`cv-auto` 도 N에 비례) → 리레이아웃이 skip 을 무효화한다는 뜻. 무효화 경로를 다시 봐야 함
- C2 실패 (`plain` 이 선형이 아님) → 대조군 설계 오류. 항목의 레이아웃 비용이 너무 작아 측정 한계에 묻힌 것

## 미리 적어두는 반증 요인

- **폭 변경은 화면 밖 요소도 무효화한다.** `content-visibility` 는 *렌더링*을 미루는 것이지 무효화를 막지는 않는다. 다시 보일 때 계산하면 되므로 skip 이 유지되는 게 맞다고 보지만, 아니라면 C1이 깨진다
- `contain-intrinsic-size: auto 118px` 의 `auto` 키워드는 **한 번 렌더된 항목의 실제 크기를 기억**한다. 스크롤을 안 하므로 대부분 항목은 추정치 118px 를 쓸 것이다
- 8000개 × 항목 높이 118px = 약 944,000px 문서. 뷰포트는 900px → **99.9%가 화면 밖**이다. skip 효과가 최대로 드러나는 조건
