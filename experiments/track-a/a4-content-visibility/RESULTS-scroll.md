# A4b 결과 — `content-visibility` 의 대가 (스크롤)

측정일 2026-09-17 · Chrome **152.0.7977.83** (headless=new) · 설정마다 Chrome 새로 기동 · 3회 반복
사전 등록 예측: [PREDICTION-scroll.md](PREDICTION-scroll.md) · 선행: [A4 RESULTS](RESULTS.md)
원자료: `results-scroll-r1.json` · `results-scroll-exact.json` · `results-scroll2.json`

---

## 결론 먼저

**미뤄둔 일은 사라지지 않는다. 다만 잘게 나뉜다.**

- `plain` 은 스크롤 중 `Layout` 이 **정확히 0ms** — 이미 다 해놨으니까
- `content-visibility` 는 스크롤 중 항목이 들어올 때마다 계산한다. **총량은 오히려 더 크다**
- 그러나 그 비용은 **프레임마다 잘게 흩어진다.** 한 번에 78ms 멈추는 대신 프레임당 6.7ms를 낸다

그리고 **스크롤 패턴이 결론을 뒤집는다.** 이걸 확인 안 했으면 정반대 결론을 보고할 뻔했다 (§3).

---

## 1. 스크롤 중 비용 (N=8000, 40단계 전체 스크롤)

| N | 모드 | `Layout` 횟수 | `Layout` 총ms | `Style` 총ms |
|---:|---|---:|---:|---:|
| 500 | `plain` | **0** | **0** | **0** |
| | `cv-auto` | 57 | 31.4 | 9.3 |
| 2000 | `plain` | **0** | **0** | **0** |
| | `cv-auto` | 71 | ~102 | ~14.5 |
| 8000 | `plain` | **0** | **0** | **0** |
| | `cv-auto` | 79 | **584.3** | 25.0 |

`plain` 은 어떤 N에서도 스크롤 중 레이아웃이 **한 번도 일어나지 않는다.** 스크롤은 컴포지터 일이다 — [A1에서 본 그대로](../a1-pipeline-skip/RESULTS.md).

`cv-auto` 는 N에 비례한다: 31.4 → 102 → 584.3 (N 16배 증가에 18.6배).

## 2. 사전 등록 주장 판정

| # | 주장 | 판정 | 실측 |
|---|---|---|---|
| **D1** | 스크롤 중 `Layout` 이 `cv-auto` > `plain` | ✅ | 584ms vs **0ms** |
| **D2** | `plain` 의 스크롤 중 `Layout` 은 거의 0 | ✅ | **정확히 0** |
| **D3** | `cv-auto` 의 스크롤 중 `Layout` 은 N에 비례 | ✅ | 18.6배 (N 16배) |
| **D4** | 전체 스크롤 누적 ≤ `plain` 1회 리레이아웃 | ❌ **반증** | 584ms vs 78.5ms = **7.4배** |

**D4 반증이 이 실험의 핵심 결과다.** 미뤄둔 일을 전부 치르면 원래보다 **더 비싸다.**
한꺼번에 계산하는 것(batch)보다 들어올 때마다 계산하는 것(incremental)이 항목당 비쌀 수밖에 없다.

## 3. 스크롤 패턴이 결론을 뒤집는다 ⚠️

1차 측정은 문서 전체를 **40단계로 점프**했다 (N=8000일 때 한 걸음 21,786px). 이건 스크롤이 아니라 순간이동이다.
현실적인 연속 스크롤(**300px씩 60번** = 18,000px, 약 165개 항목 통과)로 다시 재니 결과가 달라졌다.

### N=8000, `contain-intrinsic-size` 값을 바꿔가며

| 스크롤 패턴 | 모드 | `Layout` 총ms | `Paint` 횟수 | `scrollHeight` |
|---|---|---:|---:|---:|
| **점프형** (21,786px × 40) | `cv-auto` (118px, 41% 과대) | 611.9 | 97 | 1,231,608 |
| | `cv-exact` (73px, 정확) | **1,132.1** | **1,315** | 872,328 ✓ |
| **연속형** (300px × 60) | `cv-auto` (118px) | 713.7 | 122 | 1,231,608 |
| | `cv-exact` (73px) | **401.1** | 81 | **872,328** ✓ |

- 점프형에서는 정확한 값이 **1.9배 나쁘다**
- 연속형에서는 정확한 값이 **1.78배 좋다**

**측정 방법이 정반대 결론을 만든다.** 현실에서 사용자는 연속으로 스크롤하므로 **연속형이 맞는 조건**이고, 거기서는 정확한 `contain-intrinsic-size` 가 정확성과 성능 양쪽에서 이긴다.

> 점프형에서 왜 뒤집히는지는 **확인하지 못했다.** `Paint` 가 97 → 1,315로 13배 뛰는 게 단서인데, 기전은 미검증이다.

> 🔄 **후속 ([C2 §3](../../track-c/c2-anomalies/RESULTS.md#3--점프형-스크롤--기전은-맞았고-현상이-재현되지-않았다))** —
> 다른 하네스에서 같은 CSS·같은 스크롤 함수로 다시 재니 **이 표의 점프형 결과가 재현되지 않았다.**
> 거기서는 정확한 값이 점프형에서도 1.41배 **빠르다.** 위 숫자는 이 하네스 안에서는 재현성이 높지만
> (Paint 1316/1314/1316), 하네스를 바꾸면 사라진다 — 즉 `contain-intrinsic-size` 값의 성질이 아니라
> **이 페이지 구성에 딸린 현상**이다. 아래 §4 의 "연속형이 맞는 조건" 이라는 결론은 그대로 유효하다.

`cv-exact` 의 `scrollHeight` 872,328 은 `plain` 과 **완전히 일치한다.** [A4에서 유도한 73px 계산](RESULTS.md#4-contain-intrinsic-size-는-속도가-아니라-정확성을-위한-것)이 맞았다는 확인이다.

## 4. 총량이 아니라 분포로 봐야 한다

D4만 보면 `content-visibility` 가 손해처럼 보이지만, **비용이 어떻게 흩어지는지**가 진짜 이야기다.

| | `plain` | `cv-exact` (연속 스크롤) |
|---|---|---|
| 리스트 구축·리레이아웃 시 | **78.5ms 한 방** (프레임 4~5개 날아감) | ~10ms |
| 스크롤 중 | 0ms | 401ms를 **60프레임에 분산 = 6.7ms/프레임** |
| 총량 | 적음 | 많음 |
| 체감 | **한 번 크게 멈춤** | 멈춤 없음 (프레임 예산 안) |

**`content-visibility` 는 총 작업량을 줄이는 기능이 아니라, 큰 정지를 잘게 나누는 기능이다.**
[강의 02의 "즉시 렌더 vs 양보 렌더"](../../../docs/lecture/02-javascript-and-rendering.md#1-즉시-렌더-vs-양보-렌더)와 정확히 같은 거래다 — 처리량을 조금 내주고 반응성을 산다.

주의: `cv-auto`(틀린 값)는 **11.9ms/프레임**이라 120Hz(8.3ms)에서는 프레임을 떨군다. 값이 틀리면 이 이점마저 깎인다.

## 5. 정리 — 언제 쓰나

| 상황 | 판단 |
|---|---|
| 긴 리스트, 사용자가 **일부만** 봄 | ✅ 최적. 안 본 항목 값은 안 치른다 |
| 긴 리스트, 사용자가 **전부** 스크롤 | ⚠️ 총량은 7.4배 많다. 그래도 프레임 단위로는 부드럽다 |
| 리스트가 자주 리레이아웃됨 (창 크기 변경 등) | ✅ 리레이아웃 87% 절감 ([A4](RESULTS.md)) |
| 항목 100개 수준 | ❌ 이득 2.2배. 복잡도만 늘어난다 |
| 항목이 수만 개 | ❌ 여전히 O(N). **가상 스크롤**이 맞다 |

**`contain-intrinsic-size` 는 반드시 정확히.** content-box 기준이고, 틀리면 스크롤바도 성능도 같이 나빠진다.

## 6. 한계

- 스크롤을 JS(`scrollTop` 대입)로 구동했다. 실제 휠·터치 스크롤은 컴포지터 주도라 경로가 다를 수 있다
- 점프형에서 `cv-exact` 가 나빠지는 기전 미확인
- 초기 로드(파싱 + 첫 렌더) 비용은 여전히 미측정
- `cv-nosize` 는 연속형으로 재지 않았다

## 7. 자가 평가

**통과**

- D4가 반증됐고, **그 반증이 기능의 성격을 정확히 드러냈다** — "공짜로 빨라진다"가 아니라 "큰 정지를 잘게 나눈다"
- **스크롤 패턴을 의심한 게 결정적이었다.** 1차 결과(`cv-exact` 가 2배 나쁨)를 그대로 보고했다면 *"정확한 `contain-intrinsic-size` 는 오히려 해롭다"* 는 틀린 조언을 남겼을 것이다. 21,786px 점프가 스크롤이 아니라는 걸 알아챈 게 이번 라운드의 값어치
- [A4](RESULTS.md)에서 산수로 유도한 73px 이 `scrollHeight` 872,328 로 `plain` 과 정확히 일치해 **교차 검증**됐다
