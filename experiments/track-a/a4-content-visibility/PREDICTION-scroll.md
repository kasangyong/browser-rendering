# A4b 사전 등록 예측 — `content-visibility` 의 대가 (스크롤)

> **측정 전에 작성.** 2026-09-17.
> [A4 §7](RESULTS.md#7-한계) 에서 "가장 아픈 누락"으로 적은 항목을 채운다.

## 질문

[A4](RESULTS.md)는 `content-visibility: auto` 가 리레이아웃 비용을 87% 줄인다는 걸 확인했다.
그런데 **건너뛴 일은 사라진 게 아니라 미뤄진 것**이다. 항목이 뷰포트에 들어오는 순간 계산해야 한다.

**문서 끝까지 스크롤하면, 미뤄둔 비용을 전부 치르게 되는가?**

## 측정

리스트를 만든 뒤(트레이스 밖), **40단계로 문서 끝까지 스크롤**하는 구간만 트레이싱한다.

| 항목 | 값 |
|---|---|
| N | 500 / 2000 / 8000 |
| 모드 | `plain` · `cv-auto` |
| 스크롤 | 40단계, 각 단계 rAF 2회 대기 |
| 지표 | `UpdateLayoutTree` · `Layout` · `PrePaint` · `Paint` 횟수·시간 |
| 격리 | 설정마다 Chrome 새로 기동 · 3회 반복 |

## 예측

| # | 주장 | 근거 |
|---|---|---|
| **D1** | 스크롤 중 `Layout` 시간이 **`cv-auto` > `plain`** | plain은 이미 전부 레이아웃돼 있어 스크롤 시 추가 레이아웃이 없다. cv-auto는 들어오는 항목마다 해야 한다 |
| **D2** | `plain` 의 스크롤 중 `Layout` 은 **거의 0** (N과 무관) | 레이아웃은 이미 끝났고 스크롤은 합성 단계 일이다 |
| **D3** | `cv-auto` 의 스크롤 중 `Layout` 은 **N에 비례** | 지나가는 항목 수가 N이다 |
| **D4** | 전체 스크롤 시 `cv-auto` 의 누적 비용이 `plain` 의 **1회 리레이아웃 비용을 넘지 않는다** | 각 항목을 딱 한 번씩만 계산하므로 |

**D4가 핵심 질문이다.** 미뤄둔 일을 전부 치러도 "한 번씩만" 치르는 거라면 여전히 이득이다.
반대로 스크롤 중 같은 항목이 반복 계산된다면(들어왔다 나갔다 하며) `cv-auto` 가 더 비쌀 수 있다.

## 판정

- D1·D3 성립, D4 성립 → **content-visibility 는 "지연"이지 "낭비"가 아니다** → 통과
- D4 실패 (스크롤 누적이 plain 리레이아웃보다 큼) → 반복 계산이 일어난다는 뜻. 그게 이 기능의 숨은 비용
- D2 실패 → plain 도 스크롤 시 레이아웃을 한다는 뜻. 전제를 다시 봐야 함
