# C6 사전 등록 예측 — 실제 웹사이트에서도 같은 결론이 나오나

> **측정 전에 작성.** 2026-09-18.
> [C5](../c5-realistic-invalidation/RESULTS.md) 까지의 결론은 **전부 내가 만든 합성 리스트**에서 나왔다.
> 실제 페이지에서 다시 잰다.

## 왜 이걸 하나

지금까지 16개 실험의 공통 한계: **하네스를 내가 만들었다.**
항목 4,000개가 전부 같은 크기·같은 구조였고, 선택자도 단순했다.
실제 페이지는 그렇지 않다.

## 사전 조사에서 이미 나온 것 — 전제가 다르다

공개 문서 사이트 4곳을 훑어 `content-visibility` 를 걸 단위를 찾았다
([probe-structure](probe-structure.mjs) · [probe-target](probe-target.mjs) · [probe-granularity](probe-granularity.mjs)).

| | 개수 | 높이 중앙값 | 최소~최대 | **변동계수** |
|---|---:|---:|---|---:|
| **내 합성 리스트** (C1~C5) | 4,000 | 109px | 109~109px | **≈ 0** |
| **Wikipedia** `.mw-parser-output section > *` | **698** | 81px | **26 ~ 43,220px** | **3.72** |

**이게 이번 실험의 핵심 전제다.** 실제 블록은 크기가 제각각이라
`contain-intrinsic-size` 를 **하나의 값**으로 줄 수가 없다.
[C1 에서 73px 하나로 오차 1.3% 를 맞췄던 것](../c1-initial-load/RESULTS.md#4-contain-intrinsic-size-의-값이-맞는지-다시-확인됐다)은
**내가 그렇게 만들었기 때문**이지 일반적인 상황이 아니었다.

### 다른 후보들은 왜 뺐나

| 사이트 | 이유 |
|---|---|
| MDN CSS Reference | 본문 직계 자식이 **3개**뿐. 걸 단위가 없다 |
| WHATWG HTML Standard | 같은 문제 (3개) |
| Wikipedia HTTP 상태 코드 | 문서가 17,865px 로 작다 |

반복 단위가 대부분 `<tr>` 이었는데, **`contain: size` 는 테이블 내부 요소에 적용되지 않는다** —
그래서 행 단위로는 걸 수 없다. 실제 페이지에서 겪는 제약 그 자체다.

## 측정 대상

- 페이지: `en.wikipedia.org/wiki/List_of_Unicode_characters` (문서 높이 **153,105px** · DOM **47,916** 노드)
- 단위: `.mw-parser-output section > *` (**698개**)
- 모드: `plain` / `cv-auto`(`content-visibility:auto; contain-intrinsic-size:auto 81px` — 관측된 중앙값)
- 무효화: [C5 와 같은 셋](../c5-realistic-invalidation/PREDICTION.md) — 컨테이너 폭 / 항목 스타일만 / `:root` 변수(대조군)
- 반복 3회 · **엄격 격리 + 순서 섞기** ([C4d](../c4-raster-threshold/RESULTS.md#610-26배는-chromium-이-아니라-내-측정-절차였다))

> 공개 페이지를 **읽기만** 한다. 로그인·폼·쓰기 없음.
> 총 18회 로드로 제한한다 (사람이 브라우징하는 정도).

## 예측

| # | 주장 | 내 예측 |
|---|---|---|
| **Q1** | 81px 하나로는 `scrollHeight` 오차가 **30% 이상** | ✅ 변동계수 3.72 면 한 값으로 못 맞춘다 (합성에서는 1.3%였다) |
| **Q2** | 컨테이너 폭 변경에서 `cv` 가 이득 | ✅ 방향은 맞을 것. 다만 **배율은 C5(2.73배)보다 작다** |
| **Q3** | 항목 스타일만 바뀌면 `cv` 가 손해 | ✅ C5 에서 4.5배 손해였다. 실제에서도 손해 |
| **Q4** | `plain` 의 Style 이 무효화 방식에 따라 크게 다르다 | ✅ C5 에서 337배 |
| **Q5** | 전체 결론의 **방향**은 C5 와 같다 | ⚠️ **이게 진짜 시험대다** |

### 틀릴 수 있는 지점

실제 페이지는 블록이 **698개이고 크기가 제각각**이다.
[C5 의 결론(컨테이너 폭 → Layout 이득 / 항목 스타일 → 손해)](../c5-realistic-invalidation/RESULTS.md)이
균일한 4,000개에서 나온 것이라면, 698개 불균일에서는 **다르게 나올 수 있다.**

특히 `auto` 키워드는 **렌더된 실제 크기를 기억**하므로,
불균일한 실제 페이지에서는 합성보다 **오히려 잘 동작할** 여지도 있다.

그리고 실제 페이지에는 내 하네스에 없던 것들이 있다 — 이미지·폰트·스크립트·복잡한 선택자.
**Style 비용의 절대값이 합성과 완전히 다를 것**이고, 그게 결론을 바꿀 수도 있다.
