# C5 사전 등록 예측 — "이득은 Style 에서 나온다" 가 현실적인 무효화에서도 성립하나

> **측정 전에 작성.** 2026-09-18.
> [C2](../c2-anomalies/RESULTS.md) 의 결론을 그 한계 안에서 다시 검증한다.

## 검증 대상

[C2 §2](../c2-anomalies/RESULTS.md#2-예측-못-한-것--layout-패스-횟수가-늘어난다) 의 결론:

> **`content-visibility` 의 이득은 Layout 이 아니라 Style 에서 나온다.**
> Style 절감은 무효화 종류와 무관하게 일정하다(−71~76%). 흔들리는 건 Layout 쪽이다.

이건 통념(*"content-visibility 는 layout 과 paint 를 건너뛴다"*)과 어긋나는 실측이라
이 저장소에서 제일 쓸모 있는 결론이 될 수 있다. **그런데 조건이 하나뿐이었다.**

## C2 의 한계 — 세 무효화가 전부 같은 방식이었다

| C2 의 무효화 | 실제로 한 일 |
|---|---|
| `width` | `:root` 의 `--itemW` 변경 |
| `offset` | `:root` 의 `--listPad` 변경 |
| `color` | `:root` 의 `--itemBg` 변경 |

**셋 다 `:root` 의 CSS 커스텀 프로퍼티다.** 커스텀 프로퍼티는 **상속**되므로
트리 전체의 스타일이 무효화된다 — 스타일 재계산의 **최악 경우**다.

그래서 `plain` 의 Style 이 N=4,000 에서 **222ms** 나왔고,
cv 의 "Style −76%" 도 그 위에서 나온 숫자다.
[C2 한계에 적어뒀지만](../c2-anomalies/RESULTS.md#7-한계) 검증하지 않고 닫았다.

## 핵심 질문

`content-visibility` 가 건너뛰는 건 **건너뛴 서브트리의 스타일 재계산**이다.
그렇다면 **애초에 항목 스타일을 건드리지 않는 변경**에서는 **절감할 것이 없어야 한다.**

## 무효화 네 가지 — 커스텀 프로퍼티를 쓰지 않는다

| 이름 | 방법 | 무엇을 무효화하나 |
|---|---|---|
| `width-inline` | `list.style.width = '720px'` | **컨테이너 레이아웃만.** 항목 스타일은 안 건드린다 |
| `theme-padding` | `#list.compact .item{padding}` 클래스 토글 | **항목 N개의 스타일 + 레이아웃** (테마 전환 같은 것) |
| `item-color` | `#list.alt .item{background}` 클래스 토글 | **항목 N개의 스타일**, 레이아웃 없음 |
| `root-var` | C2 방식 (`:root` 커스텀 프로퍼티) | **트리 전체** — 대조군으로 유지 |

앞의 셋이 현실에서 흔한 방식이고, 마지막이 C2 가 쓴 최악 경우다.

모드는 `plain` / `cv-auto`, N 은 500 / 4,000.

## 예측

| # | 주장 | 내 예측 |
|---|---|---|
| **P1** | `width-inline` 에서 Style 절감이 **거의 없다** (±20% 이내) | ✅ 항목 스타일을 안 건드리니 건너뛸 게 없다 |
| **P2** | `theme-padding` · `item-color` 에서는 Style 절감이 **크다** (≥50%) | ✅ 항목 N개 재계산을 건너뛴다 |
| **P3** | `root-var` 의 절감이 넷 중 **가장 크다** | ✅ 최악 경우니까 |
| **P4** | `plain` 의 Style 절대값이 `root-var` 보다 다른 셋에서 **훨씬 작다** | ✅ 5배 이상 차이 |
| **P5** | 그래도 파이프라인 **전체**로는 `cv` 가 네 경우 모두 이긴다 | ⚠️ `width-inline` 에서는 **질 수도** 있다 |

### 그래서 예상되는 결론

**C2 의 "이득은 Style" 은 조건부로 참일 것이다** —
*무효화가 항목 스타일을 건드릴 때만.* 컨테이너만 바꾸는 변경에서는 Style 절감이 없고,
[C2 §2 에서 본 Layout 증가](../c2-anomalies/RESULTS.md#2-예측-못-한-것--layout-패스-횟수가-늘어난다)만 남아
**cv 가 손해일 수 있다.**

그렇다면 C2 의 문장은 이렇게 좁혀져야 한다:
*"이득은 Style 에서 나온다"* → *"항목의 스타일을 재계산해야 하는 변경일 때만 이득이 있다"*

## 측정 절차 — [C4d](../c4-raster-threshold/RESULTS.md#610-26배는-chromium-이-아니라-내-측정-절차였다) 의 수정을 적용한다

이 실험이 **엄격 격리를 처음부터 쓰는 첫 실험**이다.

- 이전 브라우저가 **완전히 종료될 때까지** 기다린 뒤 +3초 (기존: `kill` 후 0.5초)
- 측정 시작 시점의 **살아 있는 chrome 프로세스 수**를 매 실행 기록
- 조건 **순서를 섞어서** 실행 ([방법론 18](../../../README.md#방법론-19조))
- 설정마다 **5회** 반복, 반복별 값을 먼저 본 뒤에 평균을 낸다

시간 차이가 **2배 미만**이면 "차이 없음" 으로 읽는다 — C4d 에서 잰 흩어짐(1.6배)이 그 정도다.
