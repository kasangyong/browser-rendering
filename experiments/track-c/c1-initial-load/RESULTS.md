# C1 결과 — 초기 로드 비용

측정일 2026-09-18 · Chrome **152.0.7977.83** (headless=new, GPU 가속) · 설정마다 Chrome 새로 기동 · 캐시 비활성 · 3회 반복
항목을 **HTML 에 미리 박아둔 정적 파일**(최대 959KB)을 내비게이션해서 파싱부터 LCP 까지 트레이싱
사전 등록 예측: [PREDICTION.md](PREDICTION.md) · 생성기 [gen.mjs](gen.mjs) · 원자료 [results.json](results.json)

---

## 결론 먼저 — 초기 로드와 리레이아웃은 다른 이야기였다

[A4](../../track-a/a4-content-visibility/RESULTS.md) 에서 `content-visibility` 가 **여전히 O(N)** 이라고 결론냈다.
초기 로드에서는 **그렇지 않다.**

| | 리레이아웃 ([A4](../../track-a/a4-content-visibility/RESULTS.md)) | **초기 로드 (C1)** |
|---|---:|---:|
| `plain` 의 Layout 스케일링 | 78.1배 (N 80배) | 5.74배 (N 20배) |
| `cv-auto` 의 Layout 스케일링 | **21.4배** | **0.96배 — 평탄** |
| 항목당 Layout 비용 | 9.8µs → 1.25µs (7.8배) | 36µs → **측정 한계 아래** |

**A4 하나만 보고 "content-visibility 는 O(N)이라 별로다"라고 말했다면 틀린 조언이었다.**
내가 잰 건 리레이아웃이었고, 이 기능이 광고하는 건 초기 로드였다.

## 2. 초기 Layout 은 항목 수와 거의 무관해진다

```
Layout (ms)
166 ┤                                        ╭─ plain
    │                                    ╭───╯
 59 ┤                    ╭───────────────╯
 29 ┤━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━  cv-auto
    └────────────────────────────────────────
     200               1,000            4,000  (항목 수)
```

| 모드 | N=200 | N=4,000 | 배율 |
|---|---:|---:|---:|
| `plain` | 28.9ms | 165.6ms | **5.74배** |
| `cv-auto` | 30.6ms | 29.4ms | **0.96배** |
| `cv-nosize` | 26.2ms | 37.5ms | 1.43배 |

### 선형 모델로 분해하면

`plain` 을 `고정비 + 항목당 × N` 으로 맞추면:

```
28.85 = f + 200k
165.64 = f + 4000k
→ k = 0.036 ms/항목 (36µs) · f = 21.7 ms
```

`cv-auto` 는 기울기가 **음수로 나온다**(30.55 → 29.43). 항목당 비용이 노이즈(±3ms)에 묻혔다는 뜻이다.

> ⚠️ **"O(1) 이 됐다"고 말하지 않는다.** 이론상 N개 상자의 위치는 여전히 계산해야 하므로 O(N) 이다.
> 다만 항목당 비용이 `plain` 의 **1/100 이하**로 떨어져 **측정 한계 아래**로 내려갔다는 것이 정확한 서술이다.

## 3. LCP 도 실제로 빨라진다 — 내 예측이 틀렸다

| N | `plain` | `cv-auto` | 단축 |
|---:|---:|---:|---:|
| 200 | 94 ms | 73 ms | 22% |
| 1,000 | 108 ms | 66 ms | **39%** |
| 4,000 | 130 ms | 83 ms | **36%** |

예측할 때 *"LCP 요소는 화면 맨 위라 모드와 무관할 것"* 이라고 적었다. **틀렸다.**

이유는 단순하다 — **레이아웃이 끝나야 첫 페인트가 나온다.** `plain` 은 화면 밖 3,990개까지
전부 배치한 뒤에야 첫 화면을 그릴 수 있다. 그 166ms 가 LCP 를 그대로 밀어낸다.

N=200 에서는 차이가 작고(22%, 노이즈 큼) N≥1,000 에서 뚜렷해진다.

## 4. `contain-intrinsic-size` 의 값이 맞는지 다시 확인됐다

| N=4,000 | `scrollHeight` | 진짜 높이 대비 |
|---|---:|---:|
| `plain` (진짜) | 441,611 px | — |
| `cv-auto` (73px 지정) | 436,074 px | **−1.3%** |
| `cv-nosize` (미지정) | 148,214 px | **−66%** |

[A4 에서 산수로 유도한 73px](../../track-a/a4-content-visibility/RESULTS.md#4-contain-intrinsic-size-는-속도가-아니라-정확성을-위한-것)
(= 실제 109px − padding 24 − border 2 − margin 10) 이 **오차 1.3%** 로 맞았다. 세 번째 교차 검증이다.

`cv-nosize` 는 문서가 **1/3 로 쪼그라든다.** 게다가 N=4,000 에서는 Layout 도 27% 더 걸렸다(37.5 vs 29.4ms) —
**정확성뿐 아니라 속도에서도 지정하는 쪽이 낫다.**

## 5. 사전 등록 주장 판정

| # | 주장 | 판정 | 실측 |
|---|---|---|---|
| **G1** | `ParseHTML` 은 세 모드가 거의 같다 | ✅ | 18.1 / 21.5 / 25.0ms (노이즈 범위) |
| **G2** | 초기 Layout 이 `cv-auto` 에서 70% 이상 감소 | ⚠️ **조건부** | N=4,000 **82%** · N=1,000 56% · N=200 **−6%** |
| **G3** | 초기 Layout 이 여전히 N에 비례 | ❌ **반증** | **0.96배** — 측정 한계 아래 |
| **G4** | LCP 는 세 모드가 비슷하다 | ❌ **반증** | N≥1,000 에서 **36~39% 단축** |
| **G5** | `cv-nosize` ≈ `cv-auto` | ⚠️ **부분** | N=1,000 동일 · N=4,000 은 27% 나쁨 |

**5개 중 2개 반증, 2개 조건부.** 예측 적중률로는 최악이지만, 그 덕에 A4 의 결론 범위를 좁힐 수 있었다.

## 6. 그래서 A4 와 왜 다른가 — 가설

두 실험의 결정적 차이는 **무엇으로 무효화했느냐**다.

| | A4 (O(N)) | C1 (평탄) |
|---|---|---|
| 무효화 방법 | 컨테이너 **폭 변경** | 최초 레이아웃 |
| `contain-intrinsic-size: auto` 의 기억값 | 이미 렌더된 항목의 **실제 크기를 기억** → 폭이 바뀌면 무효 | 아직 기억한 게 없음 → **지정값 그대로 사용** |

**가설**: 폭이 바뀌면 `auto` 가 기억하던 크기가 쓸모없어져, 건너뛴 항목도 다시 계산해야 한다.
→ A4 의 O(N) 은 `content-visibility` 의 성질이 아니라 **폭 변경이라는 무효화 방식의 성질**일 수 있다.

**미검증이다.** 확인하려면 폭을 바꾸지 않는 무효화(예: 색 변경)로 A4 를 다시 돌리거나,
`contain-intrinsic-size` 에서 `auto` 키워드를 빼고 고정값만 줘서 비교해야 한다. → [C2 후보](#7-다음에-할-것)

## 9. 자가 평가

**통과**

- **A4 의 결론 범위를 좁혔다.** "content-visibility 는 O(N)" 은 *리레이아웃에 한한* 이야기였고,
  초기 로드에서는 항목당 비용이 측정 한계 아래로 떨어진다. 한 실험의 결론을 다른 조건에 일반화하면 안 된다는 걸
  내 데이터로 확인한 셈이다
- **예측 5개 중 2개가 반증됐다.** 특히 G4(LCP 비슷)를 틀린 게 값졌다 —
  "레이아웃이 끝나야 첫 페인트가 나온다"는 당연한 사실을 예측할 때 놓쳤다
- 항목을 **HTML 에 박아 넣은 것**이 설계의 핵심이었다. JS 로 만들었으면 파싱 비용이 빠져
  A4 와 같은 측정을 반복했을 뿐이다
- `73px` 이 세 번째로 교차 검증됐다 (A4 산수 → A4b scrollHeight → C1 scrollHeight 오차 1.3%)
